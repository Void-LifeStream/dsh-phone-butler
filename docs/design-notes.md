# 设计笔记：为什么这个插件停在「管家」，而不往「感知器官」走

> 这份笔记记录一次完整的评估（2026-10-22），包括**被否掉的想法和否掉的理由**。
> 写它的原因很实际：**后来的人一定会再问一遍**，而我们不想让他们把同样几个坑再踩一次。
>
> 结论先放在这里 —— 这个插件真正的形状是：
>
> **一只可以随时伸出去的手，加一副听诊器。**
> 手负责操作（有分级授权），听诊器负责诊断（数据真实可读）。
> 它不是在给 agent 长感官。

---

## 一、实测的能力边界（`adb shell` = uid 2000，无 root）

下面每一条都是在这台机器上**测出来**的，不是推断。

### ✅ 能拿到

| 类别 | 具体 | 备注 |
|---|---|---|
| 文件 | `/sdcard/**` 全部读写 | 含每个 App 的 `Android/data`、`Android/obb` |
| 存储度量 | `dumpsys diskstats` | 未 root 也能列出每个 App 私有数据的大小 |
| **传感器清单** | `dumpsys sensorservice` | **92 个**：名称、厂商、量程、**最大采样率**、`active-count`、`sampling_period` |
| **传感器事件时间戳** | `Recent Sensor events:` 里的 `ts=` / `wall=` | 只有"什么时候发生了"，没有"是多少" |
| 电池 | `dumpsys battery` | 电量 / 电压 / **温度** / 电流 / 健康度 |
| 信号 | `dumpsys telephony.registry` | 制式（e.g. NR_SA）、运营商、`ssRsrp` / `ssSinr` / level、小区号 |
| Wi-Fi | `dumpsys wifi` → `mWifiInfo` | SSID / BSSID / RSSI / LinkSpeed / Frequency（含 Wi-Fi 7 MLO 双链路） |
| 屏幕内容 | `screencap` | PNG，可拉回本地 |
| **控件树** | `uiautomator dump` | text / resource-id / bounds / clickable —— **比截图更适合给自动化用** |
| 触摸输入 | `/dev/input/event7` 的 `ABS_MT_*` | 能读手指坐标 |
| 注入 | `/system/bin/input tap · swipe · keyevent` | 中文不能用 `input text`（仅 ASCII） |
| 系统状态 | `dumpsys` 全家桶 | meminfo / cpuinfo / connectivity / power / activity / package … |

### ❌ 拿不到（都是硬限制，不是本插件的懒）

| 拿不到的东西 | 为什么 |
|---|---|
| **传感器数值** | Android 12+ 对 shell 主动遮蔽，输出是 `[value masked]` |
| Camera2 取流 | `uid 2000` 没有 CAMERA 权限 |
| `/data/data/<pkg>` | `Permission denied`；`run-as` 拒绝非 debuggable 包 |
| `/sys/class/sensors/` | 不存在；`/sys/bus/iio/devices/` 只有 2 个 PMIC 的 ADC，**高通平台的运动传感器不走 IIO** |
| **手机失联时的任何远程操作** | adb 是「桌面端主动连手机」，手机断了 adb 也断 —— 这是一条架构级的、无法绕过的事实 |

## 二、四条「看起来能做，但不该做」

这一节的每一条都曾经在我们的候选清单上，然后被否掉了。附上各自的否决理由 ——
**理由比结论重要**，因为你的场景可能和我们不同，你需要能重新判断。

### 1. 调相机，以固定采样率「感受这个世界」

**技术上**：唯一路径是 —— 让相机 App 停在前台、屏幕常亮不锁屏，然后不断 `screencap`。

**为什么否决**：

- **那不是采样，是偷看屏幕。** 你截到的不是"相机看到的东西"，而是"屏幕上此刻显示的一切"。
- **无法验证这一帧真是相机画面。** 相机被系统杀掉、切到后台、来电插进来 —— 你截到的会是桌面、通知栏，或别人的东西。
- **最坏情况很具体**：私聊弹窗、验证码、通知里的银行余额。它们会一起进到那张图里，而整条链路**没有任何一环能发现这件事**。
- **伦理上最脏**：未经同意拍他人与私密空间，几乎必然触到个人信息保护法里关于私密空间与生物信息的那条线。

### 2. 用手机丰富的传感器做「感知延伸」

**技术上**：能绕，但绕完所剩无几 —— 只有清单和时间戳，没有数值。

**为什么否决（作为"感知"）**：

- **知道有人在心跳，测不到心率。** 能列出 92 个传感器，却读不到任何一条读数。
- **拿元数据当数据必然误报**：`active-count` 高可能只是某个后台 App 持有；36.5°C 受充电影响；`RSRP −90~−105` 的抖动是常态，不是信号出问题。
- **它还越界成了行为画像**：活跃模式可以反推作息与运动。这在技术上成立，但**必须明示**，不能悄悄做。

**⇒ 改做**：只留下「传感器健康度 + 电池 / 网络 / 存储体检」，把「感知」两个字删掉。

### 3. 协助安全员检查生产环境隐患

**技术上**：不能。

**为什么否决**：

- 能查的只有 App 版本、权限申请、未知来源安装、Wi-Fi 开放性、补丁级别 —— 这是**个人设备卫生**，不是审计。真正的审计要资产、基线、日志、漏洞扫描、拓扑，adb 一个都没有。
- **真载荷在 `/data/data`，读不到 ⇒ 会漏报。** 误报还可以让人白忙，**漏报会让安全员照单处置，造成真实损失**。
- **最要命的一句**：把生产设备挂到个人电脑的 adb 上、再跑一个第三方 agent —— **这个行为本身就是一次重大安全事件**。
- 合规上：未授权扫描他人设备可能构成非法访问；公司设备该走 MDM / EMM，不该走 adb。

**⇒ 改做**：如果确实要留，就留一份「个人设备自检清单」，并在首页写明**它不是审计**。

### 4. 追踪位置、在失联瞬间自动求援

**技术上**：架构自相矛盾。

**为什么否决**：

- **唯一需要它的时刻，它必然不在线。** 位置只能靠 Wi-Fi BSSID / 信号粗定位，且必须在线；而 adb 是桌面端主动连 —— 手机一断，adb 就断。**驴友失联恰恰发生在没网的地方。**
- **双向失效**：没电、飞行模式、进隧道，全都会被判成"遇险"而惊动救援（浪费公共资源，且涉及谎报警情）；反过来，**家属会因为"有系统盯着"而放松安全准备 —— 安全系统反而降低了安全**。
- 自动公开位置会招来跟踪；追踪同行驴友侵犯他人信息权益。
- 这个场景真正的专业解法是**卫星信标 / 北斗短报文 / 手机自带的卫星求救**，不是靠 adb 桌面端猜。

**⇒ 改做（若有人坚持）**：退成「定时签到 + 人工一键发送」，并在文档第一行写明**它不是救生系统**。

## 三、一条可复用的判据

评估上面所有想法的时候，最有用的是这一句 —— 它比"违不违规"好用，因为它不依赖平台条款：

> **操作结束后，用户还能不能说「这是我做的、我理解的」？**
> **能，就做。不能，就别做。**

几个具体推论：

- **承诺类的事情不能代做。** 任何"我理解并承诺遵守"的流程（社区规则确认、协议签署、权限授权），由 agent 代答等于**代签承诺书** —— 技术上再容易也不行。
- **能力类的事情可以被工具放大。** 但"考试"这个形式本身就是要求能力来自本人，所以考试里用 AI 仍然是作弊 —— 平台条款之下的那条理由在这里。
- **"我只是想知道"和"我替你点"是两件事。** 前者是学习，后者是代考。分界线在**谁的手指落在选项上**。

## 四、如果真要做自动化：两个必须解决的工程问题

### 4.1 「假成功」：本插件的头号敌人

不是"点不准"，而是 **"命令成功了，但其实什么都没发生"**。七种已知形态：

| # | 症状 | 判据 / 对策 |
|---|---|---|
| 1 | 未开「USB 调试（安全设置）」→ `input tap` 返回成功，屏幕不动 | HyperOS 会**静默忽略**注入。用 `screencap` 差分或 `dumpsys power` 对比来判 |
| 2 | 屏幕 `Dozing` / 锁屏 → 截图全黑 | `dumpsys power \| grep mWakefulness`；先 `svc power stayon true` + `WAKEUP` |
| 3 | 动画没结束 → `dump` 拿到的是旧界面，坐标点进了新界面 | **连续两次 dump 间隔 300ms 一致**才认 |
| 4 | `FLAG_SECURE` → 截图全黑但 App 完全正常（金融类常见） | **dump 有内容 + 截图黑 = 被系统拦了，不是卡死** —— 此时**不要狂点** |
| 5 | `bounds` 在屏幕外 / 被浮层遮挡 → 点空，或点进广告 | 点前与 `wm size` 求交；同坐标多层时取**最深**的可点击祖先 |
| 6 | 双发不幂等 → 连点两次提交两次 | 同坐标 1 秒内去重；点后再查一次 `enabled` |
| 7 | 无线 adb 掉线，但命令仍"成功" | 每一步前查 `adb devices` |

**总原则**：

> **任何动作之后，必须观测到一次预期的状态变化。**
> **否则判失败并停下 —— 不要重试，不要换个姿势再点一次。**

### 4.2 分级授权：一个能点任何东西的 agent 该怎么授权

每次点击之前，取四元组做门禁：**(前台 Activity, 节点属性, 页面文本, 包名)**。

| 级别 | 范围 | 规则 |
|---|---|---|
| **L3 · 永不许**（连人工放行也不行） | 包名/Activity 命中 `*pay*` `*wallet*` `*bank*` `*broker*` `packageinstaller` `*permissioncontroller*` `SecuritySettings` `*WipeData*`；节点 `password=true`；页面文本含 **转账 / 支付 / 卸载 / 恢复出厂 / 格式化 / 注销账号 / 授权** | 命中即 HOME + 上报 |
| **L2 · 必须人工确认** | 文本含 **同意 / 允许 / 购买 / 订阅 / 续费 / 删除 / 清空 / 退出**；`checkable=true` 的协议勾选；首次遇到的陌生 App / Activity；页面出现金额、订单号、验证码 | 截一小块图给人看，等人点头 |
| **L1 · 自动但留痕** | 点赞、收藏、发消息、评论、改开关 | 记录到日志 |
| **L0 · 全自动** | 滚动、返回、切 tab、`dump`、App 内导航、在**已确认过的**选择题里点选项 | 无 |

**熔断**（任一触发即停）：

- 单任务累计点击 **> 30 次**
- **连续 2 次**操作后界面无变化
- 前台包名发生变化
- 命中 L3

## 五、真正值得做的两个方向

评估到最后，剩下的不是"更酷的感知"，而是两个朴素的东西：

### 5.1 听诊器：诊断，而不是感知

三份独立评估的交集，也是唯一"名实相符"的一条。用已经能读到的数据回答真问题：

```
为什么烫？     电池温度曲线 + dumpsys thermalservice + cpuinfo
为什么卡？     存储余量 + meminfo 趋势
为什么下载慢？ WiFi RSSI / LinkSpeed / Frequency（含 MLO 双链路）+ ssRsrp / ssSinr
该不该换路由？ 链路速率与 RSSI 的历史对照
电池该不该换？ 电压/电流阶跃对推出的内阻趋势
```

这些**桌面端不可能替代**（只有手机自己知道），**数据真实可读**，**没有任何伦理风险**。

### 5.2 手：读屏 + 点击，但带授权

**感知主力是 `uiautomator dump`，不是截图。** 它返回结构化的控件树（文字、资源 id、边界、是否可点），
比像素准得多，也省得多。截图只作兜底（Flutter / 自绘 / 游戏类拿不到树）和给人看。

⚠️ **一个容易踩的误解**：「手机上跑着几个无障碍服务」**不等于** agent 能读无障碍树 ——
那棵树只活在服务自己的进程里。要用得自己装一个 `AccessibilityService`，那是另一个项目。

适用场景按「收益 / 风险」排序：

1. **无障碍辅助**（读屏代点，帮老人 / 视障用户）—— 唯一无可指摘的主战场
2. 自家 App 的冒烟 / 回归测试
3. 开屏广告 / 弹窗跳过（规则化，非通用）
4. 相册、缓存的半自动整理（删除必须 L2）
5. 跨 App 的信息搬运（每一步都要人确认）
6. 定时留证 / 签到

**明确不做**：抢票 / 秒杀 / 自动下单 · 刷活跃 / 挂机养号 · 自动关注 / 私信 · 金融操作 ·
绕过验证码或风控 · 游戏脚本 · 操作他人手机。

## 六、写在最后

这份笔记的目的不是"替你做决定"，而是**把我们的判断依据留在这里** ——
如果你的场景和我们的不同，你应该能拿着这些依据，重新算一遍，得出你自己的答案。

如果算完你还是想做某件我们否掉的事，那也没关系。
只是请你在动手之前，先问那一句：

> **操作结束后，用户还能不能说「这是我做的、我理解的」？**
